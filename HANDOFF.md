# MBK Assistant — руководство по развёртыванию (handoff)

Документ для разработчика партнёра. Цель — поднять контейнер на своём сервере, подключить
OpenRouter и проверить работоспособность. Время на развёртывание при готовых доступах — ~30 минут.

---

## 1. Что это и как устроено

Чат-ассистент квалификации лидов. Два контейнера через `docker compose`:
- **backend** — FastAPI, вся логика, обращается к LLM через OpenRouter.
- **frontend** — статика React + nginx, проксирует `/api/*` на backend.

Состояние сессий — в памяти + снапшоты в `logs/`. БД не требуется.

---

## 2. Предварительные требования

- Linux-сервер (Ubuntu 22.04+/Debian 12+), 2 ГБ RAM, 1 vCPU, Docker + docker-compose-plugin.
- **Доступ к OpenRouter.** Это главный момент — см. раздел 4.
- Аккаунт OpenRouter с пополненным балансом (на старт хватит $10).

---

## 3. Быстрый старт

```bash
git clone <репозиторий> mbk && cd mbk
cp .env.example .env
nano .env          # заполнить ключ и параметры доступа (раздел 4)
docker compose up -d --build
./test_api.sh      # смоук-тест
```

Откроется на `http://<IP>:<MBK_PORT>` (по умолчанию порт из `.env`, переменная `MBK_PORT`).

---

## 4. Доступ к OpenRouter из РФ — ВЫБЕРИТЕ ОДИН ПУТЬ

OpenRouter (openrouter.ai) из российского сегмента часто недоступен напрямую и не принимает
оплату российскими картами. Поэтому в `.env` нужно настроить один из двух путей.

### Путь А — прокси на иностранном VPS (рекомендуется для полного контроля)

1. Арендуйте дешёвый VPS за пределами РФ (Нидерланды/Финляндия/Германия, ~$5/мес).
2. Поднимите на нём прокси. Пример с tinyproxy (3 команды):
   ```bash
   apt-get update && apt-get install -y tinyproxy
   # в /etc/tinyproxy/tinyproxy.conf: Port 3128, и добавить "Allow <IP-вашего-RU-сервера>"
   systemctl restart tinyproxy
   ```
3. В `.env` основного сервера:
   ```
   OPENROUTER_PROXY=http://<IP-иностранного-VPS>:3128
   OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
   OPEN_ROUTER_API_KEY=sk-or-...    # ваш ключ OpenRouter
   ```
4. Оплата OpenRouter — с иностранной карты или через посредника пополнения баланса.

### Путь Б — российский OpenAI-совместимый шлюз (проще с оплатой)

Сервисы вроде ProxyAPI.ru/Vsegpt принимают рубли и проксируют в OpenRouter под капотом.
```
OPENROUTER_BASE_URL=https://api.proxyapi.ru/openrouter/v1   # endpoint вашего шлюза
OPEN_ROUTER_API_KEY=<ключ-шлюза>                            # ключ шлюза, не OpenRouter
# OPENROUTER_PROXY не нужен
```
Прокси не требуется. Минус — наценка шлюза на токены.

**Проверка доступа до запуска:**
```bash
# с прокси:
curl -x http://<IP-VPS>:3128 -I https://openrouter.ai/api/v1/models
# через шлюз:
curl -I https://api.proxyapi.ru/openrouter/v1/models
```
Если приходит ответ (200/401) — канал работает. Таймаут/отказ — проблема сети, не кода.

## 5. Ключевые переменные `.env`

| Переменная | Назначение |
|---|---|
| `OPEN_ROUTER_API_KEY` | Ключ OpenRouter (или шлюза). Обязательно. |
| `OPENROUTER_BASE_URL` | Endpoint. Дефолт — прямой OpenRouter. Меняется для шлюза. |
| `OPENROUTER_PROXY` | HTTP-прокси для пути А. Пусто = прямое соединение. |
| `OPENROUTER_TIMEOUT` | Таймаут запроса, сек. Через прокси можно поднять до 180. |
| `OPENROUTER_MODEL` | Разговорная модель. По умолчанию `qwen/qwen3.7-max`. |
| `OPENROUTER_EXTRACTOR_MODEL` | Модель-извлекатель. По умолчанию `deepseek/deepseek-v4-pro`. |
| `ENABLE_PII_MASKING` | Маскировка ПД перед отправкой в LLM. 1=вкл (оставьте включённой). |
| `MBK_PORT` | Внешний порт фронта. |
| `MBK_AUTH_USERNAME` / `MBK_AUTH_PASSWORD` | Базовая авторизация входа. |
| `LANGFUSE_*` | Трейсинг (необязательно). |

---

## 6. Маскировка персональных данных

При `ENABLE_PII_MASKING=1` в зарубежные LLM уходит обезличенная копия:
- ФИО → только имя (для живого обращения), фамилия/отчество скрыты;
- телефон скрыт полностью;
- дата рождения → только год;
- адрес → только город/регион.

Финансовые суммы, параметры авто и недвижимости сохраняются — без них ассистент не работает.
**Оригинал ПД остаётся на этом сервере** (в `logs/` и в памяти сессии) и используется при
выгрузке лида в CRM.

Не покрывается (остаточный риск, по согласованию отложен): если клиент сам впишет адрес или
данные документа в свободном тексте — частично ловится регекспами, но не гарантированно.

---

## 7. Интеграция: куда уходит лид

Когда ассистент доводит клиента до передачи, формируется лид. Endpoint выгрузки задаётся
переменной (см. `lead_delivery.py`). Укажите ваш webhook (CRM/Telegram-бот/n8n) — туда уйдёт
JSON с полными данными клиента. Без указания лиды пишутся в `logs/leads.jsonl`.

---

## 8. Эксплуатация

```bash
docker compose logs -f backend     # логи
docker compose up -d --build       # обновление после git pull
docker compose down                # остановка
```

Логи и снапшоты: `logs/dialogs.jsonl`, `logs/leads.jsonl`, `logs/sessions/{id}.json`.
**Важно:** `logs/` содержит ПД клиентов в открытом виде — не выкладывайте наружу, настройте ротацию.

## 9. API (для встраивания в свой фронт)

Если хотите встраивать чат в свой интерфейс, а не использовать наш фронт — backend
самодокументирован: после запуска откройте `http://<IP>:8000/docs` (Swagger).

Ключевые эндпоинты:
- `POST /api/session` — создать сессию (с анкетой `{"anketa": {...}}` или без `{"anketa": null}`).
- `GET /api/session/{id}/stream?message=...` — SSE-стрим ответа (без message = авто-старт).
- `POST /api/session/{id}/end` — завершить сессию.

SSE-события: `chunk` (токены) → `bubbles` (готовые сообщения) → `state` (обновлённое состояние) → `done`.

## 10. Если что-то не работает

| Симптом | Причина | Решение |
|---|---|---|
| `test_api.sh` висит на health | backend не поднялся | `docker compose logs backend` |
| Ответ модели не приходит, таймаут | нет доступа к OpenRouter | проверьте раздел 4, `curl` через прокси |
| HTTP 401 от OpenRouter | неверный ключ / не пополнен баланс | проверьте ключ и баланс на openrouter.ai |
| HTTP 402 | кончился баланс | пополните |
| Первый ответ ~30+ сек | холодный старт провайдера | норма для первого хода, дальше быстрее |
